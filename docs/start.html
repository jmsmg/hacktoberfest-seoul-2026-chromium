시작하기

Chromium 테이블에서는 Chromium 문서(docs/)에서 없는 파일을 가리키는 링크 한 줄을 고쳐 Gerrit에 CL을 올립니다. 전체 소스를 받거나 빌드하지 않고, 문서 폴더만 1분 안에 받습니다.

오늘의 결과물#

  • Gerrit CL 링크 1개와 리뷰어 2명. 오늘은 업로드와 리뷰 요청까지 합니다.
  • 머지는 리뷰를 받은 뒤입니다. 커미터 두 명이 +1을 주고 커미터가 Commit-Queue +2를 걸면 봇이 검사하고 머지합니다. 참가자가 직접 머지할 수는 없습니다.
  • 머지되면 메일이 오고, Chromium 커밋 기록과 AUTHORS 파일에 내 이름이 남습니다.

전체 흐름#

  1. 사전 준비 — Google 계정, CLA 서명, Gerrit 로그인, depot_tools. 집에서 30~60분 걸립니다.
  2. 이슈 카드에서 카드 하나를 고릅니다.
  3. 첫 CL 올리기 — 소스 받기, 고치기, 커밋, 업로드.
  4. 리뷰 받기 — 리뷰어 2명 지정, 코멘트 대응, 머지.

막히면 막혔을 때를 먼저 보고 멘토를 불러 주세요.

문서 카드를 끝내고 더 해 보고 싶다면 코드 카드가 있습니다. Chromium 전체를 빌드해야 해서 행사 뒤 집에서 합니다.

GitHub가 아닙니다#

Chromium은 GitHub PR을 받지 않습니다. GitHub의 chromium/chromium은 읽기 전용 미러이고, 코드 리뷰는 Gerrit에서 CL(Change List) 단위로 합니다. fork도 PR도 없고, 대신 Gerrit, CL, 패치셋이라는 말을 씁니다. 낯선 말은 용어에 모아 두었습니다.

GitHub 계정은 이 사이트의 이슈 카드에 댓글을 다는 데만 씁니다.
