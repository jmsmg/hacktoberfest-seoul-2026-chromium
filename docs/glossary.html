용어

오늘 자주 듣게 될 말입니다.

용어 뜻
CL (Change List) GitHub의 PR에 해당하는 변경 하나. 로컬 브랜치 하나가 CL 하나입니다
패치셋 같은 CL을 다시 올릴 때마다 생기는 판. git commit --amend 뒤 다시 올리면 패치셋 2가 됩니다
Gerrit Chromium의 코드 리뷰 사이트, chromium-review.googlesource.com
WIP Work in progress. 처음 올린 CL의 상태로, Start Review 전에는 리뷰어에게 보이지 않습니다
커미터 Chromium에 직접 머지할 권한이 있는 사람. 커미터가 아닌 사람의 CL은 커미터 두 명의 +1이 필요합니다
Code-Review +1 리뷰어의 승인. LGTM(Looks Good To Me)이라고도 합니다
CQ (Commit Queue) 빌드와 테스트를 돌리고 통과하면 머지하는 봇. Commit-Queue +2는 머지, +1(dry run)은 검사만 요청합니다
presubmit 업로드 전에 내 컴퓨터에서 도는 검사. 오류가 있으면 업로드되지 않습니다
OWNERS 폴더마다 승인 권한자를 적은 파일. docs/는 커미터라면 누구나 승인할 수 있습니다
AUTHORS 기여자 명단. 첫 CL에 내 이름을 한 줄 넣습니다
CLA 기여자 라이선스 동의서. 서명해야 CL이 머지될 수 있습니다
depot_tools Chromium 개발 도구 모음. git cl, git new-branch, gclient가 들어 있습니다
sparse checkout 저장소의 일부 폴더만 받는 git 기능. 오늘은 docs/와 몇 폴더만 받습니다
crbug Chromium 이슈. crbug.com/<번호>가 issues.chromium.org의 이슈입니다
Gitiles 저장소를 웹으로 보여 주는 사이트. 마크다운을 렌더링해 보여 줍니다
